2 · Method — a mechanism, step by step

How the mechanism fixes a bad case

Example: 4 items, and everything goes to Item 1.

1. Measure two things per item:
$f$ = what it actually gets (a count)
$P$ = its average score
2. Score $= N \sum_i f_i P_i$
Here: $4 \times (\underbrace{1 \times 0.70}_{\text{1}} + \underbrace{0 \times 0.10}_{\text{2}} + \underbrace{0 \times 0.10}_{\text{3}} + \underbrace{0 \times 0.10}_{\text{4}}) = $ 2.8
Balanced: $4 \times (4 \times 0.25 \times 0.25) = $ 1.0 (the lowest).
3. Fix: a count cannot be trained, so training changes $P$: down for crowded items, up for idle ones.

Why not use $P$ alone? The pitfall it avoids, in one line.

The mechanism in code

import numpy as np

def softmax(z):
    z = np.exp(z - z.max(-1, keepdims=True))   # subtract max for stability
    return z / z.sum(-1, keepdims=True)

def select(x, W):
    """x: [T, d] inputs. W: [d, N] selector weights."""
    probs = softmax(x @ W)                      # [T, N]
    choice = probs.argmax(-1)                   # top-1 per input
    gate = probs[np.arange(len(x)), choice]     # its probability
    return choice, gate
